# V5 — 물리적 정확도 (크기·접촉·앵커)

**절대 크기와 접촉 정확도는 확정하지 않았습니다.** 기준물(자·알려진 물체)이 찍힌 영상, 실제 제품을 든 영상이 없습니다(BLOCKED). 아래는 **코드와 수학에서 확인 가능한 것**과 **보정 방식 설계**입니다.

## 1. 크기 추정의 수학적 분해
앱은 가방 폭(px) = 제품 폭(cm) × 손의 px/cm 로 그립니다. 손의 px/cm는 이렇게 구합니다.
- **현재(V1~V4)**: MediaPipe 3D 손 랜드마크(미터 단위)에서 9개 뼈(손목→검지·중지·약지·새끼 마디, 마디 사이 3개, 검지·중지 첫 마디)의 화면 길이 합 ÷ 3D 길이 합.
- **대체값**: 검지~새끼 마디 거리(px) ÷ 7.5cm (고정 가정).

같은 영상(`fist3`)에서 측정(`px/cm`):
| 추정 방식 | px/cm | 비율(대체값 대비) |
|---|---|---|
| 7.5cm 가정(검지~새끼 마디) | 12.76 | 1.00 |
| 3D 모델, **마디 줄 3개 뼈만** | 15.37 | 1.20 |
| 3D 모델, **9개 뼈 전체(현재)** | 18.43 | 1.44 |

- **1.44 = 1.20 × 1.20.**
  - **앞의 1.20(7.5 → 15.37)은 손 크기 가정입니다.** 3D 모델 안의 검지~새끼 마디 간격은 6.34~6.47cm(세 영상 평균)이고, 코드는 7.5cm를 가정했습니다(7.5/6.4 ≈ 1.17~1.18). **어느 쪽이 사용자의 실제 손인지는 기준물 없이 알 수 없습니다.** 일반 성인 손의 이 간격은 대략 6~7.5cm 범위(일반 통계 기억, 측정 아님)로 보이며 개인차 ±15%가 있습니다.
  - **뒤의 1.20(15.37 → 18.43)은 추정 방식의 기하 문제입니다.** 뼈별 px/cm를 보면 마디 사이 뼈 14~17, 손목 뼈 17~21, 손가락 첫 마디 20~25로 **뼈마다 크게 다릅니다(변동계수 약 20%)**. 원근 투영에서는 카메라에 가까운 부분이 더 크게 보여 배율이 다르고, 카메라를 향해 구부린 손가락은 화면 길이가 짧아져 비율이 왜곡됩니다. 가방은 **주먹 아래(마디 줄과 같은 깊이)** 에 매달리므로 마디 줄 뼈의 배율이 더 맞는 기준입니다. 9개 뼈 평균은 서로 다른 깊이의 평균이라 가방 깊이의 배율보다 약 20% 큽니다 — **수학적 선택 오류**입니다. (이 판단은 기하학적 근거이며 실측으로 검증된 것이 아닙니다.)
- **실제 페이지에서의 확인**(토트백 28cm, 같은 영상, `?scale=`): `all` 523px(18.7 px/cm), `mcp` 435px(15.5), `knuckle` 349px(12.5) → V5 기본(`mcp`)은 V3/V4보다 가방이 **17% 작게** 그려집니다.
- **회전 안정성은 평가 못 함**: 세 영상에서 손의 회전은 −20°~−13° 뿐이라 "손을 돌려도 배율이 변하지 않는가"는 시험할 수 없었습니다(BLOCKED, 영상 D 필요). 정지 구간의 변동계수는 세 추정 모두 0.1~0.6%로 안정적입니다.

### 확인한 다른 항목 (수학적 오류 없음)
| 항목 | 결과 |
|---|---|
| 단위 변환 | `px/cm = (Σpix ÷ Σmet) ÷ 100` — 3D 단위가 미터이므로 올바름 |
| 크롭 좌표 변환 | 손 확대 크롭(정사각)에서 랜드마크를 `crop.x + q.x·crop.size`로 되돌림 — 올바름(월드 좌표는 크롭과 무관) |
| 좌우 반전 | 거울 모드에서 x를 `W − x`로 변환, 각도 부호도 반전 — 올바름 |
| 화면·카메라 해상도 | 배율이 px 단위라 해상도에 비례, 가방 폭도 같은 px로 계산 — 일관 |
| 제품 크기 데이터 | 3D 렌더 가로세로비가 `product.json` 치수와 6~8% 이내 일치(V3에서 확인) |
| 원근(손 거리) | 가방이 손과 같은 깊이라고 가정. 손이 카메라에 가까울수록 원근 차이가 커짐(위 뼈별 배율 분산) |

## 2. 캘리브레이션 설계 — 방식 비교
| 방식 | 정확도 | 사용자 부담 | 구현 난이도 | 오류 위험 | 평가 |
|---|---|---|---|---|---|
| A. 실제 가방 크기를 입력 | 제품 쪽 오차는 없앰(이미 `product.json` 치수 사용) → **손 배율 오차는 못 고침** | 낮음 | 쉬움 | 의미 없음 | **불충분**(원인은 손 배율) |
| B. 손 폭 직접 입력(자로 잰 값) | 손 크기 가정 오차(①) 제거 | 중간(자 필요, 틀리게 잴 수 있음) | 쉬움 | 마디 사이 간격을 정확히 재기 어려움 | 가능 |
| C. 신용카드(85.6×54mm, 규격 크기)를 손 옆에 대고 한 번 찍기 | 절대 배율을 직접 측정 | 낮음(카드 한 장) | 중~상(카드 검출, 같은 깊이 필요) | 카드와 손의 깊이 차이 | **가장 정확하나 개발 필요** |
| D. 실제 제품을 들고 화면의 3D 가방을 슬라이더로 맞추기 | 사용자가 보는 결과에 직접 일치 | 중간 | 쉬움(이미 크기 슬라이더 있음) | 주관적, 손 자세가 바뀌면 달라짐 | **지금 당장 가능** |
| E. 기본값을 손 크기 통계로 정함 | 개인차 ±15% 남음 | 없음 | 쉬움 | 평균에서 먼 사람은 계속 어색 | 기본값으로는 충분 |

**권고**: 단기 = D(+ B 선택). 이미 `?gain=0.5~2` 곱셈 계수를 넣었고(주소 인자로만 존재), 값은 사용자별로 저장되지 않습니다. 중기 = C. **어느 방식이든 기준물 영상으로 먼저 현재 오차를 측정한 뒤 정합니다** — 사용자에게 영상 F(30cm 자 또는 A4 용지를 손 옆에 세운 영상)와 G(실제 LAGI 제품을 든 영상)를 요청했습니다(`V4-NATURALNESS.md`).
