# V3-1 — 손 유실 개선(53% → 87%) 재검증

**결론 먼저**: V2의 "가방 표시 비율 53% → 87%"는 **추적이 좋아진 것이 아니라, 오래된 위치를 더 오래 보여 준 결과**였습니다. 손이 가만히 있을 때는 맞는 처리지만, 손이 움직이던 중에 사라지면 V2는 V1보다 **더 틀린 위치에 더 오래** 가방을 남기고, 복귀할 때 **더 크게 튀었습니다.** 이전 보고서(`V1-V2-COMPARISON.md`, `FINAL-RECOMMENDATION.md`)의 "손 유실 처리: VERIFIED IMPROVEMENT"는 **정지한 손에 한해서만** 성립하므로 PARTIAL로 정정합니다.

## 무엇을 잘못 봤나
- 이전 시험 `fist3-drop`은 손이 **거의 정지한 상태**에서 검출만 끊기는 영상이었습니다. 끊기기 전/후 손 위치 차이는 3px(손바닥 폭 96px 대비), 손 속도 중앙값 0px/frame. 이런 영상에서는 "마지막 위치를 유지"가 항상 정답이라 87%가 좋아 보였습니다.
- 코드 확인: V2는 검출이 끊긴 뒤에도 최대 8회(약 0.5초) 마지막 손 위치로 그리고, 그 뒤에 350ms를 더 유지(`lastHandAt`이 계속 갱신되기 때문). 합치면 ≈0.9초 동안 낡은 위치를 보여 줍니다. V1은 0.5초.
- 추가로 발견한 결함: V2의 유지 구간(`holdHand`)에서는 **손 오버레이를 그리지 않고 곧바로 return**하므로, 이 구간에는 가방이 손가락 위에 덧칠됩니다(실제 손은 영상에 남아 있는데도).

## 새 시험 (정답 기준 있음)
같은 클립을 **끊지 않은 상태의 추적 결과를 정답**으로 두고, 클립의 일부 구간(150ms~1s)의 검출을 지운 뒤, 엔진이 그린 위치와 정답을 비교했습니다. 구간 시작 시각 7곳 × 간격 3가지. 이동이 빠른 경우는 `fist3-pan`을 시간 압축(4배·8배, **합성 속도**)해 만들었습니다. 코드 `tools/loss-study.mjs`, 원자료 `data/loss-study.json`.

지표: *표시율*(구간+400ms 중 가방이 보이는 비율), *평균 오차*(표시된 가방 ↔ 실제 손 위치, px), *잘못 표시*(오차 > 손바닥 폭 절반인 프레임의 비율), *복귀 시 최대 프레임 이동*(px/frame).

## 질문에 대한 답
| 질문 | 답 |
|---|---|
| 실제 추적 성공률이 높아졌나? | **아니오.** 검출 성공률은 V1과 같습니다. 표시 시간만 늘었습니다. |
| 잘못된 위치에 제품이 남나? | **예, 이동 중에는.** V2: 잘못 표시 22~58%, V1보다 같거나 나쁨. |
| 손이 사라졌을 때 적절한 위치에 유지되나? | 정지한 손이면 예, 움직이던 손이면 아니오. |
| 복구 시 갑자기 이동하나? | V2에서 1.5~3배 크게 튐(최대 186px/frame). |
| 빠른 움직임에서 지연이 증가하나? | 정지 시 위치 지연 +34ms(이전 측정). 빠른 구간 지연은 V1과 같은 수준이었고 개선 없음. |

## V3 처방 (`HoldPolicy`, `src/v3/fitFilter.ts`)
- 유지 시간을 **손의 직전 속도에 비례해 줄임**: 정지 시 900ms ↔ 빠를 때(손바닥 폭 1.5배/초 이상) 120ms.
- 컷으로 사라지지 않고 **120ms에 걸쳐 투명해짐**.
- 돌아오면 화면의 가방과 손이 가리키는 위치의 차이를 110ms 시정수로 **미끄러지듯 보정**.
- 검출 주기가 느린 기기에서 "유실"로 오판하지 않도록 평균 검출 간격으로 기준 시간을 보정(최소 150ms, 간격의 2.5배, 최대 2.5초).
- V3는 유지 중에도 손 오버레이를 정상적으로 그립니다.
