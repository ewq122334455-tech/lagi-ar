# 실제 결과물 품질 점검

**원칙**: 코드가 돈다는 것과 결과가 좋다는 것을 구분합니다. 아래에 "확인한 것"과 "확인하지 못한 것"을 나눠 적었습니다.

## 1. 무엇을 실제로 확인했는가

| 대상 | 확인 방법 | 상태 |
|---|---|---|
| 실시간 3D 착용 — **추적 신호** | 사용자 본인의 손 녹화 영상(`fist3`, 15fps)을 프레임별로 MediaPipe HandLandmarker에 넣어 **실제 추적 출력 180프레임**을 얻음. 이 출력에 V1·V2 평활을 똑같이 적용해 측정 | **실측** (`data/realtime-sim-results.json`) |
| 실시간 3D 착용 — **화면** | 이전 세션에서 사용자가 보낸 실기기 스크린샷(제품 5종), 이번 세션의 가짜 카메라 렌더 캡처 | **눈으로 확인** (개인 얼굴·손이 있어 저장소에는 넣지 않음) |
| 실시간 3D 착용 — **실제 FPS·발열·배터리** | 샌드박스는 소프트웨어 WebGL이라 렌더가 약 1~2fps | **미검증** (실기기에서 측정 필요) |
| AI 영상(Decart) | 사용자가 이전에 실행한 실제 AI 영상 스크린샷 | **눈으로 확인** (아래 Q2) |
| AI **사진** 합성 결과물 | 유료 Gemini 호출이 필요해 **이번 세션에서 생성하지 않음** | **미검증 — 실제 생성 품질은 평가하지 못했습니다** |
| AI 제품 컷아웃(사진 합성의 참조 이미지) | 저장된 실제 Gemini 결과 파일을 원본 사진과 나란히 비교 | **눈으로 확인** (`images/tote-cutout-vs-original.jpg`) |

> 모의(가짜) AI 응답으로 통과한 테스트(photofit, greenlive 등)는 **화면 흐름의 검증이지 AI 생성 품질의 검증이 아닙니다.** 이 문서에서 품질 근거로 쓰지 않았습니다.

## 2. 실제로 확인된 품질 문제

| ID | 구분 | 증상 | 근거 | 상태 |
|---|---|---|---|---|
| Q1 | AI 사진 · 참조 이미지 | 합성에 쓰는 제품 참조(컷아웃)가 **AI가 다시 그린 그림**이라 원본과 다름. 토트백에서 주머니 질감이 매끈하게 바뀌고 손잡이 안쪽 그림자·바닥 모양이 달라짐 | `images/tote-cutout-vs-original.jpg` (왼쪽 컷아웃 / 오른쪽 원본) | **확인됨** (토트백 1종을 눈으로 비교. 나머지 7종은 컷아웃 파일이 없어 비교하지 못함) |
| Q2 | AI 영상 · 모델 | 디자인 고정 이전의 AI 영상은 **LAGI 제품이 아닌 다른 가방**(예: 글자 "EARF.FIO"가 적힌 토트)을 그림 | 사용자 스크린샷(이전 세션) | **확인됨** — 이후 "디자인 고정"(초록 영역에 우리 사진 덮기)으로 완화. 모델 자체의 한계는 남음 |
| Q3 | 실시간 3D · 추적 | 검출이 최대 22Hz(원본 영상 15fps)인데 렌더는 60Hz라 위치가 **계단 모양**으로 움직임. 빠른 이동에서 프레임 간 가속도 RMS 5.1px/frame² | 실측 (`fist3-pan`) | **확인됨** — V2도 같은 수준(5.7). 해결하지 못함 |
| Q4 | 실시간 3D · 추적 유실 | 손이 1초 사라지면 V1은 가방이 **53%만 보이고 최대 550ms 동안 사라짐**, 돌아올 때 바로 붙음 | 실측 (`fist3-drop`) | **개선됨** (V2: 87%, 최대 217ms) |
| Q5 | 실시간 3D · 회전 | 손 회전 각도의 프레임 간 가속도 RMS가 V1 0.006~0.008 → **V2 0.001~0.002** (4~6배 안정) | 실측 | **개선됨** |
| Q6 | 실시간 3D · 렌더링 | 가방에 **접촉 그림자가 없고** 손과 가방이 떠 보임. 조명은 화면 평균 밝기로 세기만 조절 | 사용자 스크린샷 | **미해결** |
| Q7 | 실시간 3D · 모델 | 3D 모델이 사진 기반 근사치(부드러운 피크닉백도 단단한 상자로 표현) | 코드·모델 데이터 | **미해결** (원 데이터 필요) |
| Q8 | 데이터 | 데일리 파우치백, 북커버는 3D 모델이 없어 실시간 3D 불가 | `product.json` | **차단** (제품 사진 필요) |
| Q9 | UX · 사진 | 너무 작거나 어둡거나 흐린 사진을 올려도 알려 주지 않고 유료 호출을 진행 | 코드 | **개선됨** (부드러운 안내, 차단하지 않음) |
| Q10 | UX · 결과 | AI가 구도를 자르거나 제품이 없는 사진을 내도 그대로 "완성"처럼 표시 | 코드 | **개선됨** (부드러운 안내) |

## 3. 확인하지 못한 것 (명시적 미검증)

- AI 사진 합성의 **실제 결과물 품질**: 로고·그래픽 보존, 색, 손과 제품의 접촉, 그림자, 인체 왜곡, 생성 실패율
- 실기기 FPS, 발열, 배터리, 카메라 전환·화면 회전의 체감
- 사용자 만족도 (실제 사용자 피드백 없이 판단하지 않음)

이 항목들은 `scripts/ai-fitting-ab.mjs`로 **승인 후** 유료 호출을 하면 측정할 수 있게 준비했습니다 (`IMAGE-FITTING-IMPROVEMENTS.md`).
