# V4 — 실제 착용이 부자연스러운 원인 분석

배경: V3 실기기 테스트에서 사용자가 부자연스러움을 확인했습니다. **이전 자동 시험 통과는 실제 품질 통과가 아닙니다.** 아래는 "무엇이 원인일 수 있고, 무엇을 측정으로 확인했고, 무엇은 사용자 영상이 있어야 확인되는지"를 구분한 것입니다. 수치를 임의로 바꾸거나 보기 좋다는 이유로 개선을 선언하지 않았습니다.

## 원인 목록 (상태: VERIFIED=측정으로 확인 / PARTIAL / NOT TESTED / BLOCKED=사용자 영상 필요)

### 1. 손 이동 중 제품 위치 지연 — **원인 VERIFIED(오프라인), 기기 영향 NOT TESTED**
**방법**: 녹화한 손 영상을 MediaPipe로 추적한 실제 출력(180프레임)을 정답으로 삼아, 화면에 보이는 프레임의 실제 손 위치와 V3가 그린 위치의 거리를 측정(`tools/sync-study.mjs`, `data/sync-study.json`). 단위는 손바닥 폭(검지~새끼 마디 거리, 영상에서 약 96px).
| 조건 | 감지 주기 | V3 평균 오차 | p95 오차 |
|---|---|---|---|
| 정지한 손 | 5~15Hz | 0.001 | 0.001 |
| 천천히 좌우 이동 | 15Hz | **0.175** | 0.292 |
| 〃 | 7.5Hz | 0.273 | 0.501 |
| 〃 | 5Hz | 0.365 | 0.707 |
| 4배 빠른 이동(합성) | 감지 15Hz의 4배 속도 | 0.352 | 0.622 |
| 8배 빠른 이동(합성) | 〃 | 0.524 | 0.884 |
**결론**: 오차는 손이 빠를수록, **감지 주기가 느릴수록 커집니다.** 정지 시에는 문제 없음. 휴대폰에서 감지가 5~7Hz로 떨어지면 이동 중 가방이 손에서 한 손바닥 폭의 약 1/3~1/2 뒤처집니다. 실제 감지 속도는 벤치(`detectMs`, `detectIntervalMsMean`, FPS)로 사용자 휴대폰에서 측정해야 합니다.
**가설(NOT TESTED)**: 손 감지가 메인 스레드에서 동기 실행되어(`detectForVideo`) 감지가 길면 화면 갱신 자체가 느려짐. 확인 방법: 벤치의 `fps`·`detect ms`. 사실이면 감지를 Web Worker로 옮기는 것이 근본 해결(큰 변경, V5 후보, 기기 데이터 후 결정).

**V4 시도 — 선행(lead) 보정** (`?engine=v4`, 실험): 마지막 감지 이후 경과 시간 × 손 속도만큼 위치를 앞으로 밀기(상수 튜닝 없음, 정지한 손에는 적용 안 함, 손바닥 폭의 0.6배 상한).
| 조건 | V3 오차 → lead 오차 | 프레임 간 가속도(떨림 지표) |
|---|---|---|
| 천천히, 15Hz | 0.175 → 0.112 (**−36%**) | 5.7 → 11.7px (**2.1배**) |
| 천천히, 7.5Hz | 0.273 → 0.222 (−19%) | 8.2 → 15.6 (1.9배) |
| 천천히, 5Hz | 0.365 → 0.348 (−5%) | 9.8 → 18.1 (1.9배) |
| 4배 빠름 | 0.352 → 0.278 (−21%) | 13.8 → 25.8 (1.9배) |
| 정지 | 변화 없음 | 변화 없음 |
**판정: PARTIAL.** 위치 오차는 줄지만 **움직임이 거칠어지는(가속도 2배)** 대가가 있고, 그것이 눈에 어떻게 보이는지는 실기기에서만 알 수 있습니다. 그래서 기본값이 아닌 **실험용 옵트인**으로만 두었고, 개선이라고 선언하지 않습니다. (이전에 같은 아이디어를 버린 이유와 동일한 절충 — 이번에는 오차를 함께 측정해 양쪽을 기록.)

### 2. 제품 회전과 손 회전의 불일치 — **BLOCKED (영상 필요)**
손 회전각(`handYawOf`)은 검지~새끼 마디선의 3D 깊이 차에서 계산합니다. V2에서 각도 떨림은 4~6배 줄었음을 확인했지만(녹화 추적 기준), **"손이 실제로 90°/180° 돌 때 제품이 같은 각도로 도는가"의 정답이 없습니다**(회전 방향 부호, 손등/손바닥 전환 시 뒤집힘 등). 영상 필요: 아래 D.

### 3. 손잡이와 손의 접촉 위치 오류 — **BLOCKED (영상·사진 필요)**
손잡이 꼭대기를 "주먹 아래 +3cm"에 두는 규칙(`gripCm`)은 **눈으로 본 결과에 맞춘 값이지 실측값이 아닙니다.** 실제 제품을 같은 손으로 든 사진/영상과 비교해야 맞는지 알 수 있습니다. 영상 필요: 아래 G. 맞지 않으면 제품별 `gripCm`을 데이터로 조정할 수 있게 해 두었습니다(변경 전에는 값 없음).

### 4. 제품의 관성·움직임 — **NOT TESTED (주관적)**
진자(`Swing`)는 정지 시 0°, 이동 시 최대 ≈10°로 시뮬레이션에서 안정적이지만, **사용자가 느끼기에 과한지 어색한지는 영상으로만 확인**됩니다(감쇠비 0.35·최대각 25°는 물리 상식에 맞춘 값이지 사용자 평가에 맞춘 값이 아님). 확인용으로 `&off=swing`을 붙이면 흔들림만 끌 수 있게 했습니다.

### 5. 손과 제품 사이의 가림 — **UNSOLVED (깊이 필요)**
손이 앞에 오는 경우만 처리. 팔·몸이 제품 앞/뒤인 경우는 깊이 정보 없이 판단 불가. `&off=mask`로 손 후광 정리만 끌 수 있음.

### 6. 제품 크기·색상·재질의 원본 불일치
- **색**: 조명 이득 측정으로 V3에서 0.98 — **VERIFIED**(통제 시험). 재질(광택·반사)은 **NOT TESTED**.
- **크기 — 새로 발견한 큰 의심점 (VERIFIED 불일치, 정답은 BLOCKED)**: 앱은 손 크기를 두 방법으로 추정할 수 있습니다. ① MediaPipe 3D 손 스케일(`handScale`, 현재 사용), ② 검지~새끼 마디선 = 7.5cm 가정. **같은 녹화 영상에서 두 추정이 1.38~1.45배 차이**납니다(예: 18.4 vs 12.8 px/cm). 즉 어느 쪽이 맞는지에 따라 **가방이 실제보다 약 40% 크거나 작게** 그려질 수 있습니다. 어느 쪽이 사용자 손에 맞는지는 자(尺)나 크기를 아는 물체를 손 옆에 둔 영상이 있어야 판정됩니다(아래 F). 이 크기 오차는 "부자연스럽다"의 가장 큰 후보 중 하나입니다.
  - 주먹을 쥔 상태에서는 마디선 간격이 펼친 손(7.5cm 가정이 성립)과 달라 ②도 부정확할 수 있습니다.
  - 확인 후 해결 방안: 두 추정 중 맞는 쪽을 선택하거나, 사용자가 손을 펴서 한 번 보정(예: 화면의 자에 맞추기)하는 단계 추가 — **영상 결과 후 결정**.

## 진단용 스위치 (실기기에서 "무엇이 어색한가"를 가려내기)
주소 끝에 `&off=swing,grip,mask,shadow` 중 원하는 것을 붙이면 해당 부분만 꺼집니다.
| 스위치 | 끄는 것 |
|---|---|
| `swing` | 가방 흔들림(관성) |
| `grip` | V3의 손잡이 위치 규칙(V2 방식으로 복귀) |
| `mask` | 손 오버레이 후광 정리 |
| `shadow` | 접촉·바닥 그림자 |
엔진 비교: `engine=v1|v2|v3|v4`. 예) 같은 제품에서 `v3` → `v3&off=swing` → `v3&off=grip` 순으로 보며 "어느 것이 어색한지" 알려 주세요.

## 사용자 영상 요청 (BLOCKED 항목 해소용)
**어떻게 찍나**: 휴대폰 기본 카메라 앱으로 **일반 동영상**을 찍습니다(앱 화면 녹화가 아닌 원본). 같은 동작을 앱 화면 녹화로도 한 번씩 찍어 주세요(가상 가방이 보이는 쪽). 각 10~15초, 밝은 곳, 단색 배경, **손만 나오게**(얼굴이 나오면 잘라 주시거나 알려 주세요). 다른 사람이 나오면 안 됩니다.
| 코드 | 찍을 내용 | 해소하는 항목 |
|---|---|---|
| A | 가방을 든 손을 가만히 10초 (정면) | 기준, 떨림 |
| B | 손을 좌우로 천천히 3번 | 1 (위치 지연) |
| C | 손을 빠르게 3번 흔들기 | 1, 복귀 튐 |
| D | 손을 천천히 돌리기: 손등 → 옆 → 손바닥 → 다시 처음, 2번 | 2 (회전) |
| E | 손을 화면 밖으로 뺐다가 되돌리기 3번 | 유실·복귀 |
| F | **30cm 자(또는 A4 용지)를 손 바로 옆에 세워 두고** 손을 펴서 5초, 그다음 주먹을 쥐고 5초 | 6 (크기) |
| G | **실제 LAGI 제품**을 같은 손으로 5초 든 영상 + 앱에서 **같은 제품**을 같은 자세로 가상 착용한 화면 캡처 | 3 (접촉), 6 (크기·색) |
**받은 뒤 분석 계획**: 원본 영상을 현재의 오프라인 파이프라인(추적 → V1/V2/V3/V4 재생 → 지표)에 그대로 넣어 같은 입력으로 비교하고, 앱 화면 녹화와 나란히 보며 사용자가 어색하다고 느낀 시점을 맞춥니다. 영상은 분석 후 삭제하며 저장소에 넣지 않습니다.
