# LAGI AI 피팅 — 실제 품질 검증 환경 (LAB)

엔진을 더 만들지 않고, **지금 있는 V1~V5를 사람이 직접 비교·판정할 도구**를 만들었다. 이 문서는 사용법과 "무엇이 검증됐고 무엇이 아닌지"를 정직하게 적는다.
유료 API(Gemini/Decart)는 한 번도 호출하지 않았다. 운영 배포·main 병합·인터넷 공개도 하지 않았다.

## 1. 로컬에서 실행하는 방법

```bash
npm ci
VITE_LAB=1 npm run build          # 랩 전용 빌드 (공개 빌드에는 랩 코드가 없다)
npx vite preview --port 4190      # 로컬에서만 연다
# 브라우저: http://localhost:4190/#/lab?product=plano-bag&engines=v2,v3,v5
```

- `localhost`는 카메라 권한이 허용된다. 휴대폰은 기존 `scripts/device-test-server.mjs`(HTTPS, 접근 제한)를 쓴다.
- `npm run dev`로 `VITE_LAB=1`을 주는 방식은 **검증하지 않았다**(빌드+preview 방식만 검증).
- 공개 빌드(`npm run build`, VITE_LAB 없음)에는 `#/lab`이 없고 코드도 번들에 없다(grep 확인).

## 3. 실제 카메라 vs 녹화 영상 — 구분

- 카메라 입력: 화면에 "실제 카메라"로 표시. 이 환경(클라우드 컨테이너)에는 카메라가 없어 **가짜 카메라(y4m 파일)**로만 실행했다 → 이것은 실기기 검증이 아니다.
- 녹화 영상 입력(`파일 선택`): 화면에 "녹화 영상 — 실기기 검증 아님"이 표시된다. 같은 영상을 모든 엔진이 똑같이 받으므로 **엔진 간 상대 비교**에는 쓸 수 있으나, 실제 손떨림·조명·기기 성능은 반영하지 않는다.
- 실기기에서만 알 수 있는 것: 실제 FPS, 지연, 손-가방 접촉의 자연스러움, 절대 크기. 아직 **미검증**.

## 4. 제품 크기 검증 (`node scripts/check-product-sizes.mjs`)

상품 데이터(`product.json` 치수) ↔ 3D 모델 치수 ↔ 면 텍스처 비율을 비교한다. 결과는 `data/product-size-check.json`.

| 제품 | 결과 |
|---|---|
| origami-picnic-bag, milkpack-earphone-case | 데이터 일관 |
| plano-bag | 3D 높이 15.4 ≠ 14cm, 3D 깊이 8.9 ≠ 14cm → **확인 필요** |
| modular-bag-s | 3D 높이 16.6 ≠ 14cm, 3D 깊이 8 ≠ 2.5cm → **확인 필요** |
| daily-tote | 치수는 일치, 바닥 텍스처 비율 26% 차이 |
| daily-pouch-bag, book-cover | 3D 모델 없음 → 실시간 착용 불가 |

주의: "데이터 일관"은 **서류상 일치**일 뿐 실물 치수가 맞다는 뜻이 아니다. 줄자로 잰 실측이 없어 절대 정확도는 단정하지 않는다.
카메라 거리별 크기 분석은 저장된 추적 시리즈와 랩의 보정 기능으로 가능하지만, **기준물을 들고 찍은 실제 영상이 없어 거리별 정확도는 측정하지 못했다.** 손 크기 추정 3종의 비율(1.44)은 알려져 있으나 어느 쪽이 실제에 가까운지는 기준물 영상이 있어야 정해진다.

## 5. AI 사진 합성 검증 준비 (`scripts/ai-eval-kit.mjs`) — 유료 호출 없음

원본 상품 사진, 컷아웃, 인물 사진, V1/V2/V2+실물면 프롬프트, 생성 결과를 한 폴더에 모아 **블라인드 평가표(rate.html)**를 만든다(방식 이름은 점수를 매긴 뒤에 공개). 항목: 형태·로고·색·손잡이 구조·소재·인물 보존·합성 자연스러움·구도 유지·제3의 손.
- 테스트는 **픽스처(상품 사진을 결과 대신 사용)**로만 했다. 즉 평가표 동작은 검증했지만 **Gemini 생성물의 품질은 평가된 적이 없다.**
- 실제 생성은 `scripts/ai-fitting-ab.mjs`(드라이런 기본, `--yes` + `LAGI_AB_CONFIRM_PAID=yes` + `--max-usd` + `--consent` 필요). 이번에 실행하지 않았다.

### 11개 중 "남은 3개"에 대하여
저장소 데이터에는 **실제 확인된 상품이 8개**(daily-tote, daily-pouch-bag, origami-picnic-bag, plano-bag, modular-bag-s, milkpack-earphone-case, book-cover, 안경 보관함)다. 11개라는 숫자와 맞는 나머지 3개를 데이터에서 특정할 수 없다. 후보는 ① 내용 미정 placeholder(`product-001`: 이미지 없음, 가격 CONTENT_REQUIRED) ② 사이트에 노출되지 않는 샘플 의류 8종(AI_DRAFT). 임의로 만들어 채우지 않았다.
필요한 자료: 확인된 상품명·가격, 정면 클린 사진, 실측 치수(cm), 3D가 필요하면 면별 텍스처. 어떤 3개인지 알려 주면 같은 도구로 바로 점검한다.

## 6. 비용 검증

- 단위 = Gemini 이미지 HTTP 시도 1회(텍스트 0.1). 호출 **전에** Durable Object에서 원자적으로 예약, 실패 시 닫힘(차단), 환불 없음.
- Gemini(`tryon`)와 Decart(`rt`)는 별도 카운터/한도. 한도 소진 시 429/503 + 사유 메시지로 안전 중단.
- 테스트/운영 분리: `wrangler.staging.toml`, `check-worker-config.mjs`(배포 게이트). 새 유료 서비스는 자동 활성화되지 않는다.
- **신규**: 시도 대비 결과 기록(원장). 시도마다 `http_ok/http_429/http_503/network_error`, 결과마다 `image/no_image/blocked`를 DO에 집계, `GET /admin/usage`(ADMIN_TOKEN 필요)가 예약 유닛·결과 분포·추정 USD를 반환. **청구서가 아니다** — 시도 수와 Google 청구 사이의 차이(실패/차단 호출이 청구되는지)는 Google 결제 페이지와 비교해야 한다. 원장이 고장 나도 호출 허용 여부에는 영향이 없다(테스트 확인).
- 시도 상한은 USD 상한을 보장하지 않는다(단가 변동). Google 쪽 예산/할당량 설정은 소유자 몫.

### A/B 예상 비용 (추정치, 호출하지 않음)
상품 3 × 스타일 2 × 방식 3(V1, V2, V2+실물면) × 2회 = 36회 + 컷아웃 3회 = **39유닛 ≈ USD 1.56**(유닛당 0.04 가정). 재시도가 모두 발생하는 최악은 117유닛 ≈ **USD 4.68**. 단가는 현재 가격을 확인한 값이 아니다.

## 7. 사용자가 촬영/준비해야 할 것
1. 줄자와 함께 가방을 든 손 영상(가까이/보통/멀리, 각 5초) — 절대 크기 검증.
2. 실제 제품을 같은 손동작으로 든 영상 + 앱 화면 녹화 — 접촉·자연스러움 비교.
3. 합성 평가용 본인 동의 인물 사진 2~3장(정면, 전신/상반신).
4. plano-bag·modular-bag-s의 실물 치수(높이·깊이) 재확인 — 3D 모델과 상품 데이터가 충돌.
5. "남은 3개" 상품 정보.
