# V4 — 외부(다중 사용자) 접속 구조 설계

**이 문서는 설계와 준비입니다. 인터넷 공개·터널 생성·배포는 하지 않았으며, 별도 승인 전에는 하지 않습니다.**

## 1. 현재 구조 분석
| 구성 | 현재 | 외부 사용자 관점 |
|---|---|---|
| 사이트 | GitHub Pages(`deploy.yml`, main 푸시 시 배포) — 정적 파일, HTTPS, 공개 | 어디서나 접속 가능. **이미 다중 사용자용 구조** |
| 카메라·손 추적·3D 렌더 | 사용자 브라우저에서 실행(MediaPipe WASM + three.js). 영상은 서버로 가지 않음 | 사용자마다 독립. 서버 상태 없음 |
| AI 사진 합성 | Cloudflare Worker `lagi-tryon`(KV + Durable Object 중계) → Gemini | 비용 발생 지점 |
| 실시간 AI 영상 | Worker가 Decart 임시 토큰 발급 → 브라우저가 Decart와 직접 연결 | 비용 발생 지점(사이트 일일 상한 100세션) |
| 시험용 LAN 서버 | `scripts/device-test-server.mjs` — 내 컴퓨터, 접근키, 60분 | 같은 Wi-Fi만. 다중 사용자·외부 접속 구조 아님 |

**핵심 결론: 외부 사용자 접속을 위해 새 서버를 만들 필요가 없습니다.** 이미 공개 HTTPS(GitHub Pages)와 Worker가 있고, 카메라 처리는 기기에서 이뤄집니다. 필요한 것은 ① 운영과 분리된 **스테이징** 사본, ② **접근 제한**, ③ **비용 상한**, ④ 관리자 도구의 **공개 빌드 제외**입니다.

## 2. 권장 아키텍처 (제한된 외부 테스트)
```
테스터 휴대폰 ──HTTPS──> 스테이징 사이트 (정적)           ← 접근 제한(아래 A/B 중 택1)
        │                    │ 카메라·추적·3D: 기기 안에서만
        └─HTTPS(AI 사진만)──> lagi-tryon-staging Worker      ← 별도 KV·별도 낮은 상한·별도 Gemini 키
                                   └─> Gemini (스테이징 전용 키)
운영: GitHub Pages(main) + lagi-tryon Worker  ← 변경 없음
```
### 스테이징 사이트 호스팅 선택지
| | A. Cloudflare Pages + Cloudflare Access | B. GitHub Pages 별도 저장소(비공개 URL) | C. 내 컴퓨터 + 직접 만든 터널(현재 방식 확장) |
|---|---|---|---|
| 접근 제한 | 이메일 허용 목록(Access, 무료 플랜 50명) — **진짜 인증** | URL을 아는 사람 누구나(비밀번호 없음) | 접근키(URL에 포함) |
| 운영 분리 | 완전 분리(별도 프로젝트·URL) | 별도 저장소 필요 | 컴퓨터가 꺼지면 종료 |
| 다중 동시 사용자 | ✔ | ✔ | 컴퓨터 회선·절전에 의존 |
| 계정 필요 | Cloudflare(이미 Worker 사용 중 → **현재 계정 재사용 가능**) | GitHub(재사용) | 터널 계정 |
| 권장 | **✔ 권장** | 비밀번호가 필요 없는 소수 시험이면 보조 | 몇 명·단기 확인용 |

**재사용 가능한 구성:** 현재 Cloudflare 계정(Worker/KV/DO를 이미 사용), 현재 GitHub 저장소, `wrangler.staging.toml`(이번에 추가), 기존 빌드 스크립트.

### 스테이징 절차 (승인 후, 이 순서로)
1. 스테이징 전용 Gemini 키 발급(저한도·별도 결제 한도). 운영 키는 쓰지 않음.
2. `server/tryon-worker/wrangler.staging.toml`의 `STAGING-ORIGIN` 교체 → `npx wrangler deploy --config wrangler.staging.toml` → `wrangler secret put GEMINI_API_KEY --config wrangler.staging.toml`.
3. 스테이징 사이트 빌드: `VITE_TRYON_API_URL=<staging worker URL> npm run build`(**운영 `TRYON_API_URL` 변수와 다른 값**). 벤치가 필요하면 `VITE_BENCH=1`도.
4. Cloudflare Pages에 배포 + Access 정책(허용 이메일) 연결.
5. 테스터 초대.
운영 `main`·`deploy.yml`·`wrangler.toml`은 건드리지 않습니다.

## 3. 다중 사용자 독립성
- **카메라·피팅 상태**: 전부 브라우저 안(메모리·`localStorage`)에 있고 서버 상태가 없음. 시험으로 확인(`pw/multiuser.mjs`): 서로 다른 영상을 쓰는 두 브라우저를 동시에 돌려 한쪽이 가만히(표준편차 0.0px) 있고 다른 쪽이 움직이는(63.9px) 동안 서로 영향이 없음, 두 쪽 모두 업로드·WebSocket 요청 0건, Worker로 가는 요청 0건.
- **서버 쪽 공유 상태**: KV 카운터(일일 상한), 제품 컷아웃 캐시(제품 사진 기준, 사용자 데이터 아님), 인메모리 요청 제한(인스턴스별).
- **한계**: KV는 원자적이지 않아 동시 요청 폭주 시 상한을 약간 넘을 수 있음(분당 제한 10회/IP로 상한이 제한됨). 정확한 상한이 필요하면 카운터를 Durable Object로 옮겨야 함(필요 시 V5).

## 4. 사진 업로드·AI 합성 API 점검
| 항목 | 현재 | 평가 |
|---|---|---|
| 인증 | 없음(익명). Origin 헤더 검사(허용 목록 외 403) | 브라우저 CORS 보호일 뿐 **비브라우저는 Origin을 위조 가능** → 아래 비용 상한이 실질 방어선 |
| 요청 제한 | 인스턴스별 메모리 10회/분/IP | 인스턴스가 여러 개면 우회 가능, 영구 상한 아님 |
| 비용 상한 | 실시간: 사이트 100/일·IP 별 한도 있음. **사진 합성: 상한 없음** | **GAP → 이번에 수정** |
| 개인정보 | 사용자 사진은 요청 본문으로만 받아 Gemini에 전달, 저장하지 않음(컷아웃 캐시는 제품 사진 기준). 오류 로그에 이미지 미기록 | 양호. 처리방침 문구는 별도 확인 필요(법적 문구는 수정하지 않음) |
| 입력 크기 | 사진 4MB, 제품 이미지 6MB 상한, 동일 출처 제품 URL만 | 양호 |
| 관리자 도구 | `?bench=1` 벤치가 공개 번들에 포함 | **GAP → 이번에 수정**(빌드 플래그) |

### 이번에 구현한 것
1. **사진 합성 일일 비용 상한**(`TRYON_DAILY_SITE` 기본 300/일, `TRYON_DAILY_PER_IP` 기본 12/일, KV 카운터): 상한 도달 시 Gemini를 호출하지 않고 429. 시험 10/10(모의 Gemini, `tools/worker-caps-test.mjs`). 값은 `wrangler.toml`에 주석으로 문서화. **기본값을 운영에 적용할지는 배포 때 승인 사항**입니다.
2. **벤치 도구 공개 빌드 제외**: `VITE_BENCH=1`로 만든 빌드에만 포함. 공개 빌드에는 벤치 코드·`lagi-bench-runs`·업로드 경로 문자열이 **0건**(검증함). 접근키는 서버 스크립트의 실행 인자일 뿐 번들에 없음(24자리 키 패턴 0건).
3. **스테이징 Worker 설정 템플릿**(`wrangler.staging.toml`): 별도 이름·KV·낮은 상한(30/일, IP당 5/일)·별도 Origin. 배포하지 않음.

### 권장하지만 구현하지 않은 것 (별도 승인·계정 필요)
- **Cloudflare Turnstile**(무료 캡차): 스크립트 남용 차단의 표준 방법. 사이트 키·비밀 키 발급 후 프런트/Worker에 검증 추가.
- **Cloudflare Rate Limiting 규칙**(대시보드): 인스턴스 간 공유되는 진짜 요청 제한.
- **Gemini 프로젝트 결제 한도**(Google Cloud 예산·쿼터): Worker 상한과 별개의 최종 안전망 — **가장 중요**.
- 테스터 로그인(Access)로 익명 호출 자체를 제거.

## 5. 제한된 외부 테스트를 시작하기 위한 조건
1. 스테이징 호스팅 방식 선택(A 권장)과 **인터넷 공개 승인**.
2. 스테이징 전용 Gemini 키와 **Google 쪽 결제 한도** 설정(사용자 작업).
3. 테스터 명단과 **촬영 동의**(얼굴이 영상·사진에 나옴) — 테스트 안내문에 "영상은 기기 밖으로 나가지 않고, AI 사진 합성은 사진이 Gemini로 전송됨"을 명시.
4. 테스터는 5~10명 이내, 기간 제한, 테스트 후 스테이징 삭제.
5. 위 비용 상한 코드가 스테이징에 배포된 것을 확인한 뒤 시작.
