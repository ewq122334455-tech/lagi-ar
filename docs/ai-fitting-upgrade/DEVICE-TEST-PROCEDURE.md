# 실기기 FPS·발열 측정 절차 (모바일)

웹 페이지가 알 수 있는 것은 **프레임 속도, 감지 시간, JS 시간, 메모리, (안드로이드) 배터리 잔량**입니다. **온도는 페이지에서 읽을 수 없으므로** 손으로 기록합니다. 아래 도구는 `#/again?...&bench=1`을 붙일 때만 켜지며 일반 사용자에게는 아무 영향이 없습니다.

## 준비
1. 대상 기기(권장 3대 이상): 저사양 안드로이드, 중급 안드로이드, iPhone. 기기명·OS·브라우저 버전을 기록.
2. 배터리 50% 이상, 절전 모드 끄기, 화면 자동 꺼짐 해제, 같은 방 온도(약 22~25℃). 다른 앱 종료. 충전 케이블 분리(충전 중이면 발열이 달라짐).
3. 시험용 빌드 주소(브랜치 미리보기)를 받아 아래 형식으로 엽니다. (운영 사이트에는 V3 도구가 **배포되어 있지 않습니다**.)

## 주소 (제품 하나당 V1·V2·V3 각각 한 번)
```
<미리보기주소>/#/again?p=plano-bag&m=map&engine=v1&bench=1
<미리보기주소>/#/again?p=plano-bag&m=map&engine=v2&bench=1
<미리보기주소>/#/again?p=plano-bag&m=map&engine=v3&bench=1
```
제품: `plano-bag`(짧은 손잡이), `daily-tote`(긴 손잡이), `milkpack-earphone-case`(소형 파우치) 최소 3종.

## 절차 (엔진 하나당)
1. 기기를 식은 상태로 두고 **표면 온도**를 기록(적외선 온도계 또는 기기의 배터리 온도 표시가 있으면 그 값). 
2. 주소를 열고 "손에 들기" → 시작. 화면 왼쪽 아래에 `fps · js · pose · hand` 패널이 보입니다.
3. 한 손으로 제품을 든 자세로 **5분** 유지. 처음 30초는 가만히, 이후 1분마다 팔을 좌우로 천천히 5회, 한 번은 손을 화면 밖으로 1초 뺐다가 되돌리기(유실·복귀 확인).
4. 5분 후 **"결과 복사"**를 눌러 JSON을 메모/메일로 붙여넣습니다. 바로 **표면 온도**를 다시 기록.
5. 기기를 5분 식힌 뒤 다음 엔진. (순서를 V1→V2→V3, V3→V2→V1로 번갈아 두 번 하면 열 누적 효과가 상쇄됩니다.)

## 결과 해석 (JSON `summary`)
| 값 | 의미 | 합격 기준(제안, 조정 가능) |
|---|---|---|
| `fpsFirstThird` / `fpsLastThird` | 앞/뒤 3분의 1 구간 평균 FPS | 마지막 구간 ≥ 24 |
| `fpsDropPct` | FPS 하락률 — **열 제한(스로틀링)의 페이지에서 보이는 신호** | ≤ 15% |
| `detectMsFirstThird` / `LastThird` | 포즈+손 감지 시간 | 마지막이 처음의 1.3배 이하 |
| `worstFps1pctLow` | 가장 나쁜 1% 프레임의 FPS | ≥ 12 |
| `longFramesTotal` | 50ms 넘는 프레임 수 | 전체의 5% 이하 |
| `batteryPctPerMin` | 분당 배터리 소모(안드로이드 Chrome만) | V2 대비 +0.3%p/분 이내 |
| 표면 온도 상승 | 수동 기록 | 5분에 +6℃ 이하, 손으로 들기 불편한 열 없음 |

V3가 V2보다 FPS가 눈에 띄게 낮거나(>10%) 발열이 크면 V3는 **기본값으로 전환하지 않고** 그림자 옵션(`realism`)만 저사양에서 끄는 방안을 검토합니다.

## 같이 확인할 눈으로 보는 항목 (체크리스트)
- [ ] 가방이 손잡이를 쥔 것처럼 보이는가 (제품 3종)
- [ ] 손을 빠르게 움직일 때 가방이 손에서 뒤처지거나 튀는가
- [ ] 손을 뺐다가 돌려놓을 때 가방이 갑자기 튀는가 / 사라졌다 나타나는 느낌이 거슬리는가
- [ ] 어두운 방·밝은 방·창가에서 색이 사진과 비슷한가
- [ ] 그림자가 부자연스럽게 보이지는 않는가(떠 보이는 사각형 등)
- [ ] 전면·후면 카메라 전환, 화면 회전 후에도 정상인가

## 한계
- 헤드리스 샌드박스 수치(소프트웨어 WebGL, 감지 1회에 수 초)는 **대표성이 없으며** 합격 기준과 비교하면 안 됩니다. 이 도구가 정상 작동하는지만 확인했습니다.
- iOS Safari는 `getBattery`와 `performance.memory`가 없어 해당 값은 비어 있습니다.
- 측정 결과는 시험용 데이터이므로 개인정보(얼굴 영상)를 저장하지 않습니다. 도구는 숫자만 모읍니다.
