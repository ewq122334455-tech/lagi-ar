# LAGI 웹사이트 — 작성 방식 가이드

사이트가 어떻게 만들어져 있고, 무엇을 어떻게 고치면 되는지 정리했습니다. 개발 경험이 적어도 따라 할 수 있게 "하고 싶은 일 → 고칠 파일" 순서로 썼습니다.

## 1. 기술 구성

- **React 18 + TypeScript + Vite** (화면), **Tailwind CSS** + 직접 만든 디자인 변수(`src/v3/tokens.css`).
- 주소는 **HashRouter**(`#/discover`)라서 서버 없이 정적 파일만으로 어디서든 돌아갑니다(GitHub Pages, 폴더 더블클릭).
- 제품 데이터는 코드가 아니라 **JSON 파일**입니다(`public/products/`). 제품을 추가·수정해도 코드를 고칠 필요가 거의 없습니다.
- AI·회원·구매평·주문은 별도 서버(**Cloudflare Worker**, `server/tryon-worker/`)가 처리합니다.

## 3. 하고 싶은 일 → 고칠 곳

| 하고 싶은 일 | 고칠 곳 |
|---|---|
| 제품 이름, 가격, 소개, 소재, 사이즈표 바꾸기 | `public/products/<id>/product.json` |
| 제품 사진 바꾸기 | `public/products/<id>/images/` 의 파일 교체 (이름 그대로) |
| 제품 추가 | 4절 |
| 제품 숨기기/삭제 | `public/products/manifest.json` 목록에서 id를 빼기 (폴더는 두어도 됨) |
| 상세 페이지 첫 문구(큰 한 줄) | `src/v3/detailCopy.ts` 의 제품 id 항목 |
| 상세 페이지 글 구조 | `src/v3/ProductInfo.tsx` |
| 분류 이름(Top, Cap …) | `src/v3/data.ts` 의 `CATEGORY_LABEL`(한글), `CATEGORY_EN`(영어) |
| WHY LAGI 문구 | `src/content/whyLagi.ts` (색은 `src/v3/pages/Why.tsx`) |
| 예시 구매평 | `src/v3/sampleReviews.ts` |
| 메뉴 항목 | `src/v3/Layout.tsx` 맨 위 `NAV` |
| 색, 글자 크기, 간격 | `src/v3/tokens.css` (`--c-blue` 등 변수) |
| 브랜드 필름 영상 교체 | `public/media/brand-film.mp4`, `brand-film.webm`, `brand-film-poster.jpg` |
| 사업자 정보, 개인정보처리방침 | `src/content/legal.ts` (채우면 하단에 자동 표시) |
| 스마트스토어 주소 | 제품 json의 `shopUrl`, 그리고 `src/v3/data.ts`의 `OFFICIAL_LINKS` |
| AI 지시문(옷/모자/가방) | `src/v3/pipelines.ts` (영상), `server/tryon-worker/src/index.ts` (사진 합성) |

## 4. 제품 추가하기

가장 쉬운 방법: **비슷한 제품 폴더를 통째로 복사**해서 고칩니다.

1. `public/products/lagi-painter-pants` 폴더를 복사해 새 id로 바꿉니다(영어 소문자·숫자·하이픈, 예: `lagi-new-pants`).
2. 폴더 안 `images/main.jpg`, `images/drawings/front.jpg`, `images/fitting.jpg`를 새 제품 사진으로 교체합니다. **흰 배경, 제품 하나**가 가장 좋습니다(AI가 이 사진을 그대로 참고합니다).
3. `product.json`에서 아래를 고칩니다(대표 항목).
   - `id`, `name.value`(한글 이름), `nameEn`(영어 이름 — **화면에는 이것이 나옵니다**), `category.value`(`Top`/`Bottom`/`Outer`/`Cap`/`Set`/`Dress`/`Bag`/`Acc.`), `price.value`(숫자)
   - `shortDescription`, `description`, `story`, `lagiSelectionReason`, `materials`, `care`, `making`, `notice`(상품정보제공고시), `sizeChart`
   - `images`/`drawings`/`fitting.image`의 사진 경로(`products/<id>/images/...`)와 `fitting.description`(**AI가 읽는 정확한 영어 설명**: 색, 소재, 무늬, 로고 위치 — 자세히 쓸수록 정확합니다)
   - 모든 항목은 `{ "value": ..., "status": ..., "source": ... }` 모양입니다. 실제로 확인한 값은 `VERIFIED`, 지어낸 값은 반드시 `AI_DRAFT`(화면에 "예시 정보 · 확인 전" 표시가 붙습니다).
4. `public/products/manifest.json`의 `products` 목록에 새 id를 추가합니다.
5. 새 분류를 쓰는 경우(예: `Cap`처럼 새 이름): `src/v3/data.ts`의 `CATEGORY_LABEL`, `CATEGORY_EN`에 이름을 추가하고, AI 영상에 쓰려면 `isWearable`/`pipelines.ts`의 `garmentOf`도 확인합니다.
6. `npm run dev`로 열어 목록, 상세, AGAIN을 확인합니다.

도구로 만들 수도 있습니다: `node scripts/add-clothing.mjs 스펙.json` (스펙 형식은 파일 맨 위 설명). 도구는 모르는 값을 비워 두고(`CONTENT_REQUIRED`) 지어내지 않습니다.

## 5. 글 작성 규칙

- 화면에 나오는 글은 **짧게**, 같은 말을 두 번 쓰지 않습니다.
- **모르는 사실을 지어서 쓰지 않습니다.** 가격·소재·제조국·수상 이력 등은 근거가 있을 때만 `VERIFIED`, 임시로 채울 때는 `AI_DRAFT`로 표시합니다.
- 제품 이름은 영어(`nameEn`), 가격은 숫자만(원 표시 없음).
- 사진은 실제 제품 사진만 씁니다. AI로 제품을 새로 그린 이미지를 제품 사진처럼 쓰지 않습니다. (확대·선명화는 무늬가 바뀌지 않는 방법만 사용했습니다.)

## 6. 개발 명령

```bash
npm install                 # 처음 한 번
npm run dev                 # 개발 서버 http://localhost:5173
npm run build               # 운영용 빌드 → dist/ (타입 검사 포함)
npm run build:offline       # 오프라인 폴더 빌드 → dist-offline/ (index.html 더블클릭으로 열림)
npx tsc -b                  # 타입 검사만
npx eslint src              # 코드 검사
```

### 자동 시험 (화면 124개 검사)
```bash
npm install -g playwright && npx playwright install chromium   # 처음 한 번
PW_MODULE=$(npm root -g)/playwright/index.mjs bash docs/ai-video-production/tests/run-ui-tests.sh
```
- 가짜 AI(모의 SDK)로 돌려서 **돈이 들지 않습니다.** 실제 AI는 호출하지 않습니다.
- 시험 중 임시 제품(`zz-test-*`)이 만들어졌다가 끝나면 지워집니다. **이 임시 파일과 시험 중 바뀐 `manifest.json`은 커밋하지 마세요.**
- 화면을 일부러 바꾼 경우(예: 문구 변경)에는 시험의 기대값도 같이 고치고, 무엇을 왜 고쳤는지 적어 둡니다. 시험을 약하게 만들어 통과시키지 않습니다.

## 7. 운영에 반영하기 (GitHub)

저장소: https://github.com/ewq122334455-tech/lagi-ar

1. 새 가지(branch)를 만들어 작업하고 push 합니다.
2. Pull Request를 만들고, **책임자 승인 후** `main`에 합칩니다.
3. `main`에 합쳐지면 GitHub Actions(`deploy.yml`)가 자동으로 빌드해 GitHub Pages에 올립니다(2~3분). 운영 주소: https://ewq122334455-tech.github.io/lagi-ar/
4. `server/tryon-worker/` 안을 고치면 `deploy-worker.yml`이 Cloudflare Worker도 자동 배포합니다(Cloudflare 토큰이 저장소 비밀값으로 필요).
5. 가끔 GitHub Pages가 일시적으로 500 오류를 내며 배포가 실패합니다. 코드 문제가 아니므로 Actions에서 **Re-run failed jobs**를 누르면 됩니다.

## 8. AI 서버(Worker) 직접 돌려 보기 (선택, 비용 발생)

로컬에서 AI까지 시험하려면 본인 키로 별도 Worker를 띄워야 합니다(운영 Worker는 운영 사이트 주소만 허용).
```bash
cd server/tryon-worker
npx wrangler login
npx wrangler secret put GEMINI_API_KEY      # 키는 입력창에만 붙여넣기. 파일·채팅에 쓰지 않기
npx wrangler secret put DECART_API_KEY      # 실시간 AI 영상용
npx wrangler dev --var ALLOWED_ORIGINS:http://localhost:5173
```
- 설정 이름(한도, 킬 스위치 등)은 `server/tryon-worker/src/index.ts` 맨 위 `Env`와 `wrangler.toml`을 보세요.
- 사이트가 부르는 서버 주소는 `src/tryon/aiTryOn.ts`의 `AI_TRYON_URL`입니다(빌드 시 `VITE_TRYON_API_URL` 환경 변수로 바꿀 수 있음).
- 시험할 때는 한도를 낮추고(`REALTIME_SESSION_SECONDS` 등) 꼭 필요한 만큼만 돌리세요. 실시간 AI는 약 0.02달러/초입니다.

## 9. 오프라인 빌드가 하는 일

`npm run build:offline` = 일반 빌드와 같은 코드를 **파일로 열어도 되는 형태**로 만듭니다(`vite.offline.config.ts` + `scripts/make-offline.mjs`).
- 하나의 일반(비모듈) 스크립트로 묶고, 글꼴(Pretendard)을 폴더에 포함합니다.
- 브라우저가 파일 열기에서는 `fetch()`로 제품 JSON을 읽지 못하게 막아서, 제품 데이터를 사이트 안에 넣고 작은 대체 코드로 읽게 합니다.
- 운영 사이트 빌드와는 완전히 별개이며 운영에 영향이 없습니다.

## 10. 자주 하는 실수

- 제품을 추가했는데 안 보인다 → `manifest.json`에 id를 넣었는지, `product.json`이 올바른 JSON인지(쉼표, 따옴표) 확인.
- 사진이 안 나온다 → `product.json`의 사진 경로가 `products/<id>/images/...`인지, 파일 이름 대소문자가 같은지 확인.
- 화면은 바뀌었는데 운영에 안 보인다 → `main`에 합쳐졌는지, Actions 배포가 성공했는지 확인(캐시 때문에 새로고침이 필요할 수 있음).
- AI가 "origin not allowed" → 운영 사이트 주소가 아닌 곳(파일, localhost)에서 운영 Worker를 부른 것. 8절처럼 본인 Worker를 쓰세요.
