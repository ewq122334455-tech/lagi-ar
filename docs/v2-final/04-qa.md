## 기능 테스트 69개 (요약)
- 홈: 로딩, 휠이 페이지를 스크롤(가로채지 않음), 스크롤에 따라 갤러리 진행, 다음 버튼, SELECTED 8개, 목록에서 장바구니 담기, WHY 4기준 공식 문구, 갤러리 뒤쪽 사진 클릭 → 앞으로 → 상세 이동, 뒤로 가기.
- 내비: 메뉴 4개 이동, 키보드 Tab 포커스, 모바일 메뉴 열기·닫기·이동, 모바일 터치 스크롤.
- 직접 접속 + 새로고침 11개 주소, 옛 주소(/ai-fit → /again, /exhibition → 홈), 소품 필터.
- 상세: 스마트스토어 링크, 초안 문구 미노출, 개발용 문구(CONTENT_REQUIRED 등) 없음, 3D 문구 없음, 장바구니, 모바일 하단 구매 바.
- AI 합성(데스크톱·모바일): 제품 선택, 착용 방식, 잘못된 형식 거절, 미리보기, 동의 전 잠금, 진행 표시, 결과 + AI 표시, 실제 제품 사진 구분, 저장(파일명·AI 표기), 다시 시도, 서버 오류 안내, 소품 착용 방식.
- 모션 줄이기: 갤러리 클릭 시 바로 이동.

## 주문·결제 43개 (요약)
바로 구매 → 주문서, 빈 양식·미동의 차단, 주소 검색 결과 입력, **서버가 계산한 금액 표시(154,000원)**, 결제위젯 영역 렌더, 결제 → 성공 페이지 → 서버 승인 → 결제 완료(주문번호·주소), 장바구니 비움, 새로고침해도 완료 화면(중복 결제 없음), 결제 취소 → 실패 페이지 + 장바구니 유지, 결제 키 없는 빌드의 안내 문구.

서버 12개: 브라우저가 보낸 가격 무시, 샘플·없는 제품 거절, 전화번호·동의 검증, 잘못된 금액 승인 거절, 정상 승인(토스 호출 시 인증 헤더·Idempotency-Key 확인), 같은 결제 재승인, 다른 결제키 거절, 다른 사이트 출처 거절, 관리자 조회 인증.

## 실제 외부 서비스로 확인하지 못한 것 (정직하게 표시)
| 항목 | 이유 | 대신 확인한 것 |
|---|---|---|
| 토스페이먼츠 실제 결제창 | 가맹 키가 없음 | 토스 SDK와 같은 형태의 대역으로 브라우저 흐름 전체, 승인 API는 같은 형식의 대역 서버로 확인 |
| 카카오 주소 검색 실제 창 | 테스트 환경의 브라우저가 외부 http 프레임을 열 수 없음(스크립트 자체는 200 응답) | 대역으로 입력 흐름 확인, 실패 시 "직접 입력" 대체 경로 |
| Gemini 실제 합성 | 비용 · 실제 인물 사진 필요 | 배포된 Worker가 응답하는 것 확인(잘못된 사진 → 400). 합성 결과는 대역 이미지로 화면 흐름 확인. 실제 합성은 이전에 사용자가 성공 확인 |
| 실제 휴대폰 카메라 | 테스트 환경에 카메라 없음 | 파일 입력 경로 확인 |
