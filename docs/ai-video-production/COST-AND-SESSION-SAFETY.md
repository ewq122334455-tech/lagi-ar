# 비용 및 세션 안전

## 핵심: 토큰 횟수 상한 ≠ 비용 상한
Decart는 **열린 세션의 초 단위**로 과금한다(문서 발췌: 720p 2크레딧/초 = $0.02/초, 미확인). 토큰 발급 횟수를 제한해도 비용이 그 횟수분 이하라는 보장은 없다. 현재 통제와 한계를 층별로 적는다.

## 통제 계층
| 계층 | 장치 | 상태 |
|---|---|---|
| 세션 길이 | 토큰 `constraints.realtime.maxSessionDuration = 20` (공급자가 강제), 페이지 카운트다운은 보조 | 코드 확인, **실제 Decart가 20초에 끊는지는 미검증** |
| 동시 세션 | **신규** DO 임대: 방문자당 1, 사이트 동시 3 | 모의 테스트 통과(9/9) |
| 일일 횟수 | DO 원자 카운터 `rt:<날짜>`: IP당 3회, 사이트 100회, 환불 없음, 카운터 오류 시 토큰 미발급 | 기존 + 재검증 통과 |
| 토큰 수명 | 30초, 허용 모델 `lucy-2.6` 하나, 허용 출처는 우리 사이트 | 테스트 8 |
| Gemini와 분리 | 범위 `tryon`(사진·컷아웃)과 `rt`(실시간 토큰)가 별도 카운터 | 확인 |
| unmetered | `TRYON_QUOTA=unmetered`는 허용 출처가 전부 localhost일 때만. 운영 출처와 함께면 차단 | 기존 차단 유지, 임대도 동일 가드 |
| 비밀키 | `DECART_API_KEY`는 Worker에만. 브라우저는 30초 토큰만 | 번들 grep 확인 |
| 사용자 영상 | 서버 저장 없음. 녹화는 기기 내부에만 | 요청 감사: `/cutout`,`/realtime/token` 외 없음 |

## 최악 비용 계산 (공식 단가 확인 전 가정: $0.02/초)
- **정상 경로**: 하루 100회 × 20초 × $0.02 = **$40/일**. IP당 3회 = 60초 = $1.20/일. 동시 3세션 = $0.06/초.
- **Gemini(컷아웃·매트·설명)**: 시도 1유닛(텍스트 0.1), 사이트 하루 400유닛 = $16/일(0.04/유닛 가정), 상품 이미지는 Worker가 캐시하므로 상품당 첫 1회.
- **보장할 수 없는 부분**: (1) 한 토큰으로 만료 전 30초 안에 여러 연결을 시도하는 스크립트 → 우리 임대는 토큰 발급만 막고 연결 수는 막지 못한다. 연결 수 상한은 공급자 계정의 동시 세션 한도(`GET /v1/realtime/quota`)에 달려 있고 그 값은 확인하지 못했다. (2) 공급자가 `maxSessionDuration`을 지키지 않을 가능성(미검증). (3) 단가 변동. (4) 소유자 계정(`REALTIME_UNLIMITED`)은 일일 한도 면제. → **Decart 대시보드에서 계정 동시 세션 한도와 월 예산 상한을 직접 설정**해야 진짜 상한이 생긴다(소유자 작업).
- 시도 대비 실제 청구 차이는 `/admin/usage`(Gemini)와 Decart 사용량 페이지를 비교해 기록한다. 실시간 쪽 사용 기록(세션 시작·종료 시각)은 아직 서버에 남기지 않는다 — **미구현**(다음 우선순위).

## 안전한 종료
한도 소진 시 429(+사유)·카운터 고장 시 503으로 토큰이 나가지 않고, 클라이언트는 '사용량 제한' 단계와 안내 문구를 보여준다. 페이지가 사라지면 `pagehide`/숨김/언마운트로 연결을 끊고 카메라를 끈다(테스트 E1, C7).

## 운영 권고 (소유자)
1. Decart 계정 동시 세션 상한을 1~3으로, 월 예산 알림/상한 설정.
2. `REALTIME_DAILY_SESSIONS`를 처음엔 10~20으로 낮춰 시작.
3. 운영 반영 전 `node scripts/check-worker-config.mjs`.
