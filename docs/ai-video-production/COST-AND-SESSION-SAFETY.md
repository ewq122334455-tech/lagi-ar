# 비용 및 세션 안전

## 핵심: 토큰 횟수 상한 ≠ 비용 상한
Decart는 **활성 생성 시간(초)** 으로 과금한다(공식 가격 페이지: 실시간 720p $0.02/초, 빠른 모드 $0.04/초). 토큰을 몇 개 줬는지와 실제 비용은 다르다. 아래는 층별 통제와, 서버가 **강제할 수 있는 것 / 없는 것**의 구분이다.

## 서버가 강제하는 것 (실제 workerd + 실제 Durable Object에서 검증)
`docs/ai-fitting-upgrade/tools/real-workerd/run-realtime.mjs` (로컬 모의 Decart 토큰 API, 외부 호출 0)

| 통제 | 검증 결과 |
|---|---|
| 사이트 동시 세션 상한(`REALTIME_MAX_CONCURRENT`, 기본 3) | 30명 동시 요청 → 토큰 3개만 발급, 27명 `busy_site` ✅ |
| 방문자당 중복 세션 | 열린 세션이 있는 방문자의 두 번째 요청 → `busy_ip`, 토큰 없음 ✅ |
| Worker 재시작 | 임대가 DO 저장소에 있어 재시작 후에도 기억(새 토큰 없음) ✅ |
| 탭 강제 종료(종료 신호 없음) | 임대가 **스스로 35초 후 만료**, 방문자가 다시 시작 가능 ✅ (클라이언트 신호를 믿지 않음) |
| 공급자(토큰 API) 실패 | 502 + 예약 즉시 반납, 바로 재시도 가능 ✅ |
| 카운터 오류 | 토큰 미발급(닫힘) ✅ (모의 DO 테스트) |
| 토큰 제약 | `maxSessionDuration` = 세션 길이(기본 20초, `REALTIME_SESSION_SECONDS`로 10~20), 모델 1개, 허용 출처 = 우리 사이트, 만료 20초 ✅ |
| 일일 횟수(IP당 3, 사이트 100) | 유지, 재검증 ✅ |
| 사용 기록 | `/admin/usage`의 `realtime`: 토큰 수, **예약 초**(토큰×세션 길이), **페이지 보고 초**, 추정 USD ✅ |
| 페이지 보고 | 보고는 **참고용**: 1회 최대 세션 길이로 잘리고, 임대·한도를 풀어주지 않음 ✅ |

## 서버가 강제할 수 **없는** 것 (솔직한 한계)
1. **실제 Decart 연결 시간**: WebRTC는 브라우저↔Decart로 직접 연결된다. Worker는 연결이 열렸는지·얼마나 열려 있는지 **볼 수 없다**. 세션 최대 시간은 토큰의 `maxSessionDuration`으로 **Decart가 강제**하는 것이며 우리가 대신 끊을 수 없다. 이 강제가 실제로 20초에 일어나는지는 실호출 전까지 **미검증**.
2. **토큰 한 개로 여러 연결**: 공식 문서에 토큰 단위 동시 연결 제한 필드가 없다. 토큰을 가진 사람이(개발자 도구 등) 만료(20초) 전에 연결을 여러 개 열면 각각 `maxSessionDuration`까지 돈다. 우리 임대는 토큰 **발급**만 막는다. 연결 수의 진짜 상한은 **Decart 계정의 동시 세션 한도**이며(`GET /v1/realtime/quota`로 조회, 초과 시 1013), 그 값을 코드로 설정하는 방법은 문서에 없다 → **소유자가 Decart 계정에서 직접 한도·예산을 설정해야 한다.** 출처 제한(`allowedOrigins`)은 비브라우저 클라이언트가 Origin을 위조하면 소용없다고 공식 문서가 밝힌다.
3. **청구와 내부 기록의 차이**: 내부 기록은 "예약 초"(토큰당 1연결이 끝까지 간다는 가정)와 "페이지 보고 초"뿐이다. Decart의 실제 청구는 "active generation" 초이고, 큐 대기·무프레임 구간이 청구되는지는 문서에 명시가 없다. **차이는 Decart 사용량 페이지와 대조해야만 알 수 있고**, 대조 절차는 SMOKE-TEST.md에 있다.
4. 빠른 모드는 2배 과금이다. 코드는 `speed`를 **보내지 않아** 표준 속도로 연결한다(UI 테스트 F1이 확인).

## 최악 비용 (공식 단가, 표준 속도)
| 시나리오 | 계산 | 비용 |
|---|---|---|
| 정상 경로, 사이트 하루 한도 | 100세션 × 20초 × $0.02 | **$40/일** |
| IP 1개 | 3세션 × 20초 × $0.02 | $1.20/일 |
| 동시 상한 | 3세션 × $0.02/초 | $0.06/초 |
| 스모크 테스트 설정(일 2회, 동시 1, 10초) | 2 × 10 × $0.02 | **$0.40/일** |
| 토큰 악용(위 2번) | 계정 동시 한도에 의존 | **우리 코드로 상한 없음** |
| 빠른 모드가 켜진 경우 | 위의 2배 | (현재 코드는 켜지 않음) |

Gemini 쪽(컷아웃·매트·설명)은 별도 범위 `tryon`의 DO 카운터: 시도 1유닛(텍스트 0.1), 사이트 하루 400유닛, 캐시. 스모크 테스트는 `GEMINI_API_KEY`를 설정하지 않아 **Gemini 비용 0**이다.

## 분리·가드
Gemini(`tryon`)와 Decart(`rt`) 카운터 분리, `TRYON_QUOTA=unmetered`는 모든 허용 출처가 localhost일 때만, `DECART_API_KEY`는 Worker에만(브라우저 번들에 없음), `scripts/check-worker-config.mjs`가 운영 설정을 점검한다. 한도 소진 시 429/503 + 사유, 화면은 '사용량 제한' 단계.

## 운영 권고 (소유자)
1. Decart 계정의 동시 세션 한도와 월 예산/크레딧 한도를 설정(우리 코드로는 대신할 수 없음). 실사용 전 `GET /v1/credits`로 잔액 확인.
2. 시험용 프로젝트·키를 따로 쓰고, 운영 키는 스모크 이후에만.
3. 첫 공개 때 `REALTIME_DAILY_SESSIONS`를 10~20으로 낮게.
