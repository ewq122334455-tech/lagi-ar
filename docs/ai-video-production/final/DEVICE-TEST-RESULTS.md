# 기기·환경 시험 결과

**실기기 시험은 하나도 실행하지 못했다.** 이 세션은 클라우드 컨테이너이고 사용자의 기기는 제 쪽에서 접근할 수 없다. 아래 표는 **시뮬레이션(헤드리스 Chromium)** 과 **실기기**를 분리한다.

| 환경 | 상태 | 비고 |
|---|---|---|
| macOS Chrome 실기기 | **NOT VERIFIED** | 사용자의 Mac에서 설정(키, 사전 점검)까지 완료. 카메라 시험은 미실행 |
| iPhone Safari | **NOT VERIFIED** | WebRTC·`getUserMedia`·`MediaRecorder`(MP4) 동작은 실기기 필요 |
| Android Chrome | **NOT VERIFIED** | |
| 태블릿·저사양·느린 네트워크 | **NOT VERIFIED** | 서버 불통 문구는 시뮬레이션(요청 차단)으로만 확인 |
| 화면 회전·백그라운드 전환 | **NOT VERIFIED** | 탭 이동/숨김 시 세션 종료는 시뮬레이션 통과 |
| 발열·메모리·배터리·실제 FPS | **NOT VERIFIED** | 모의 FPS(약 28)는 근거 아님 |

## 시뮬레이션 결과 (실기기 아님)
- 휴대폰 크기 화면(390×844, 터치·모바일 에뮬레이션): 가로 스크롤 0px(세션 전·후), 무대가 화면 안, 세션이 `live`→`ended`, 상품 상세 링크 표시, 페이지 오류 0, 녹화 미지원 환경에서 녹화 옵션 숨김.
- 미지원 브라우저(WebRTC 없음): 안내 문구와 '미지원' 단계, **유료 요청 0건**.
- 카메라 사용 중(`NotReadableError`): "다른 앱이나 탭" 안내, 유료 요청 0건.
- 서버 불통: "AI 서버에 닿지 못했습니다. 인터넷 연결을 확인" 안내.

## 다중 사용자
- 세션 분리: 카메라·연결은 각 탭에서 독립(브라우저 내). 서버는 방문자별 임대와 일일 카운터로 분리(실제 workerd 11/11).
- 3D 손 착용(무료 모드) 두 영상 동시: 8/8(독립성, 업로드·Worker 요청 0).
- **실제 AI 영상 동시 사용자 시험: NOT VERIFIED.**

## 실기기 시험 방법 (승인 후, 사용자 작업)
1. 같은 Wi-Fi의 휴대폰에서 쓰려면 HTTPS 개발 서버가 필요하다(기존 `scripts/device-test-server.mjs`, 접근 제한형). Safari는 HTTPS 또는 localhost에서만 카메라를 허용한다.
2. 표의 항목마다 측정 기록 JSON(FPS, 끊김, 해상도, 실제 세션 시간)과 녹화본을 저장한다.
3. 발열·배터리는 시험 전후 기기 상태를 사람이 기록한다.
