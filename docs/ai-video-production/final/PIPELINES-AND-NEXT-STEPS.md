# 실시간 AI 피팅 — 파이프라인 구현 보고 (무료 단계까지)

**상태**: 코드와 모의(가짜 응답) 테스트까지 끝남. **유료 호출은 한 번도 하지 않았고, 운영 사이트는 바꾸지 않았다.** 아래 "검증됨"은 모의 테스트 기준이며, 실제 AI 결과 품질은 **미검증**이다.

## 2. 원본 제품 이미지 보존

- 제품 데이터의 **대표 사진(`main.jpg`)은 연출 사진**(벽에 걸림·손에 듦·잔디 위 등)이라 누끼가 아니다.
- 반면 **`drawings/front.jpg`는 흰 배경의 깨끗한 정면 제품 사진**이다(8개 제품 모두 확인).
- 그래서 기본 경로(파이프라인 B)는 `front.jpg`를 **AI가 다시 그리지 않고 그대로** 쓴다. 하는 일은 흰 여백 잘라내기·정사각 여백·1024px 축소뿐이다(비생성).
- 기존 Gemini 재생성 컷아웃은 파이프라인 A로만 남겼다(비교용). 제품이 바뀔 수 있는 위험은 이전 조사(`ACTUAL-QUALITY-ISSUES.md` Q1)에서 확인됨.
- 한계: `milkpack-earphone-case`의 `front.jpg`에는 치수선("80")이 있고, `glasses-case`에는 얇은 외곽선이 있다. 비생성 방식으로는 지우지 못했다. 영향은 미검증.

## 3. 파이프라인 (주소 끝에 `&pipe=` — 일반 사용자는 쓰지 않음)

| 기호 | 참조 이미지 | 모델 |
|---|---|---|
| A | Gemini가 다시 그린 컷아웃 (기존) | lucy-vton-3.6 |
| **B (기본)** | **원본 정면 사진 그대로** | lucy-vton-3.6 |
| C | Extreme Precision(손님이 제품을 든 사진, 검사 통과분) | lucy-vton-3.6 |
| D | 원본 정면 사진 | lucy-2.6 |
| DC | Extreme Precision | lucy-2.6 |

- `&provider=fal`: 참조 사진을 Decart 예제와 같은 FLUX Klein 9B + LoRA로 만든다(기본은 Gemini).
- 손에 들기·어깨에 메기는 **서로 다른 지시문**을 쓰고, 모델 계열(vton / 2.6)마다 문장도 다르다(`src/v3/pipelines.ts`). 어느 문장이 더 나은지는 **유료 실험 전에는 알 수 없다**(미검증).
- 같은 영상으로 비교하는 도구: `node scripts/rt-compare-launch.mjs --clip <영상> --product <id> --pipe A|B|C|D|DC`. Worker 재시작 없이 모델이 바뀐다.

## 4. Extreme Precision (Worker `POST /realtime/prefit`)

1. 손님 카메라 화면 한 장(1024px) + 원본 정면 제품 사진 → Gemini(기본) 또는 fal이 "손님이 제품을 든 사진" 생성.
2. **검사**: 다른 호출이 원본 사진·제품 사진·생성 사진을 비교해 JSON으로 판정(가방 있음, 한 개뿐, 디자인 일치 4/5 이상, 사람 유지 4/5 이상, 손가락·팔 정상, 들린 모양이 자연스러움).
3. 통과 못 하면 **한 번 더 생성**, 그래도 못 하면 **422**로 끝내고 사진을 돌려주지 않는다. 화면은 원본 제품 사진으로 진행하고 개발자 패널에 이유를 적는다. 검사기가 고장 나도 통과 처리하지 않는다(fail closed).
4. 어디에도 저장하지 않는다(KV·DO에 사진을 쓰지 않음, 응답으로만 전달). 로그에는 이미지가 남지 않는다.
5. 비용 통제: 요청당 1유닛을 **호출 전에** 원자적으로 차감(사람당 하루 3회, 전체 하루 100회 기본), 환불 없음, 끄는 스위치 `PREFIT_DISABLED=1`, 지연 한도 40초, 시도는 최대 2회, 요청은 분당 5회 제한. Gemini 호출은 기존 사진 합성 한도(`tryon`)에도 함께 잡힌다.

모의 테스트 29개 통과(서버): 통과/불통과/두 번째에 통과/검사기 고장/응답 해석 불가/Gemini 실패/한도/원장/비밀 노출 없음.

## 5. 안정성·비용 (SDK 코드를 직접 읽고 확인)

- **토큰 만료와 세션 제한은 별개다.** 토큰 `expiresIn`은 연결 시작용(20초), 영상 길이는 `maxSessionDuration`이 따로 정함. 이미 실제 실행에서 "Session duration limit reached"가 20.8초에 뜨는 것을 확인함(`REAL-RESULTS.md`). 토큰 만료만으로 세션이 끝난다고 가정하지 않는다.
- **발견**: SDK는 연결이 끊기면 **스스로 최대 5번 다시 연결**한다(`stream-session.js: scheduleReconnect`). 다시 연결할 때마다 새 세션이 생겨 유료가 될 수 있다. → 화면이 `reconnecting` 신호를 받으면 **즉시 세션을 끝내고** "자동으로 다시 연결하지 않습니다"를 보여 준다. 첫 연결 재시도도 기본 5회에서 **1회**로 줄였다.
- **한계**: 악의적으로 토큰을 직접 재사용하는 것은 서버에서 막을 수 없다(브라우저와 Decart 사이 연결). 토큰 20초 + 세션 20초 상한 + 사람당 동시 1개 + 하루 한도로 피해를 제한할 뿐이다.
- **모바일 네트워크 사전 검사**: SDK의 `checkConnectivity`(무료, STUN 후보 수집만, Decart 세션을 열지 않음)를 토큰 요청 **전에** 실행한다. 실시간 영상이 아예 불가능한 네트워크면 아무것도 결제하기 전에 안내하고 멈춘다. 검사가 고장 나면 막지 않고 진행한다.
- 중복 유료 요청: 시작 버튼을 다시 눌러도 토큰 요청은 1번(테스트 확인). 서버에서는 사람당 동시 1세션 임대가 이미 있음.
- 브라우저 종료·탭 숨김·이동 시 세션과 카메라 정리: 기존 동작 유지(테스트 통과).
- 실제 비용 기록: 서버 `/admin/usage`에 `prefit` 항목 추가(예약 단위, 결과 분포, 추정 USD). 청구서가 아니며 Decart/Gemini/fal 결제 화면과 대조해야 한다.

## 6. 화면

- 일반 사용자는 제품 → 손에 들기/어깨에 메기 → 카메라 → 동의 → 시작만 본다.
- 측정 패널, "실제 디자인 입히기(실험)", 파이프라인 정보는 주소에 개발용 옵션(`debug`, `pipe`, `prefit`, `provider`, `map`, `model`)이 있을 때만 보인다.
- 사진 합성 탭·기존 디자인 시스템은 그대로.
- PC·모바일 실기기 확인: **미검증**(이 환경에는 카메라·휴대폰이 없음).

## 8. 아직 하지 못한 것 (미검증 목록)

- 가방 4개 파이프라인의 실제 결과 비교 (유료 필요)
- 제품 3종 이상 × 두 가지 착용 방식의 실제 영상 검증
- 정면 유지·좌우 회전·팔 움직임·걷기·흔들림·가림·화면 이탈 시험
- 실제 모바일 기기, 다중 사용자 동시 시험
- fal 이미지 1장 가격과 모델 라이선스(FLUX Klein 9B는 상업 이용 조건 확인 필요)
- "원본 텍스처 기반 추적 합성" 추가 검토: **생성형 결과가 기준에 못 미칠 때만** 검토하기로 했으므로 아직 시작하지 않음
- 최종 검토용 URL: 운영 사이트를 건드리지 않고는 만들 수 없음. 승인 후에 별도 미리보기 배포로 제공 가능
