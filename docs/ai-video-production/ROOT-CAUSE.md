# 원인 분석

"제대로 작동하지 않는다"의 원인을 코드에서 찾았다. 실제 AI 출력을 못 본 상태이므로 **코드로 확인된 구조적 문제**와 **실제 호출이 있어야 확인되는 가설**을 분리한다.

## 코드로 확인된 문제 (수정함)
| ID | 문제 | 영향 | 수정 |
|---|---|---|---|
| R1 | 시작 순서: `상품 컷아웃 + 토큰 발급`을 먼저 하고 **그 다음** 카메라 권한을 요청 | 카메라를 거부/없는 사용자도 하루 3회 한도 1회와 Gemini 유닛(컷아웃·매트·설명 최대 3건)을 소모. 비용 낭비 | 카메라 → 입력 검사 → 컷아웃 → 토큰 → 연결 순으로 변경 |
| R2 | 토큰 `expiresIn: 60`인데 권한 창에서 시간이 오래 걸리면 만료되어 연결 실패 | 첫 사용자가 권한 허용을 늦게 하면 "연결 실패"로 보임 | 토큰을 연결 직전에 발급(R1 수정으로 해결), 만료는 30초로 단축 |
| R3 | 동시 세션 제한 없음. 한도는 "토큰 발급 횟수"뿐 | Decart 과금은 열린 세션의 시간. 같은 사람이 여러 탭/기기로 동시에 열 수 있음 | DO 임대(lease): 방문자당 1세션, 사이트 동시 3세션(`REALTIME_MAX_CONCURRENT`), 자동 만료, 실패 시 닫힘 |
| R4 | `pagehide`(탭 닫기·새로고침·모바일 백그라운드 전환) 종료 처리 없음 | 일부 브라우저에서 `visibilitychange`만으로는 안 끊겨 세션이 남을 수 있음 | `pagehide`에서도 종료 |
| R5 | 한도 초과·점검 중·연결 끊김이 모두 같은 "오류" 문구 | 사용자가 무엇을 해야 하는지 모름 | 상태를 failed/disconnected/limited로 구분 |
| R6 | 영상 결과 저장은 PNG 한 장뿐 | 실시간 기능인데 영상 저장 불가 | 동의 시 로컬 MediaRecorder 녹화 → 다운로드(서버 업로드 없음) |

## 실제 호출이 있어야 확인되는 가설 (미검증)
- H1: `lucy-2.6`(범용 편집)이 가방 같은 소품의 모양·로고를 프레임마다 다르게 그린다. 근거: 이전 스크린샷(Q2). 초록 실루엣 방식이 완화하지만 손잡이·접촉 부위는 AI가 그린 것을 따른다.
- H2: 출력 스트림이 생성 전에 입력 영상을 그대로 통과시키면, 코드의 "비디오가 재생 중이면 프레임으로 간주" 폴백(`LiveTryOn.tsx` 타이머)이 **AI 영상이 아닌 것을 AI 영상처럼** 보여줄 수 있다. 실제 SDK의 `generationTick`이 항상 먼저 오는지 확인이 필요하다.
- H3: 모바일(iOS Safari)에서 `getUserMedia` 해상도 제약(1280×720, 30fps)이 발열·지연을 키운다.
- H4: 한국→Decart 서버 거리의 지연(SDK의 지역 선택 옵션 유무는 문서 접근 불가로 미확인).
